# Грамматика выражений и устройство парсера

Документ описывает, какие выражения понимает калькулятор и как они разбираются.

---

## 1. Почему не `eval()`

Первое, что приходит в голову: взять строку от клиента и передать её встроенной
функции `eval()`. Python вычислит выражение сам, и весь этот документ окажется
не нужен.

**Так делать нельзя, и это не формальная придирка к стилю.**

`eval()` выполняет **любой** код Python, а не только арифметику. Строка приходит
из сети, от кого угодно. Вместо `2 + 2` клиент отправляет выражение, которое
читает файлы, удаляет данные, запускает процессы или открывает доступ к машине.
Это называется удалённым выполнением кода и является одной из самых тяжёлых
уязвимостей, какие бывают.

Формулировка общего правила: **данные, пришедшие из сети, не являются кодом
и никогда не должны им становиться.** Разбор нужен именно для того, чтобы
провести границу между тем, что разрешено, и всем остальным.

Существует и промежуточный вариант — разобрать строку модулем `ast`, который
строит дерево, но **не выполняет** его, и затем обойти дерево, разрешая только
безопасные узлы. Он безопасен, но разбор в нём делает Python, а не мы. Здесь
выбран полностью самостоятельный разбор — в этом и состоит содержательная часть
задания.

## 2. Два этапа разбора

```
   "2 + 3 * 4"
        │
        ▼
   ┌──────────┐
   │  Лексер  │   строка → плоский список токенов
   └──────────┘
        │
        ▼
   [ЧИСЛО 2] [ПЛЮС] [ЧИСЛО 3] [ЗВЁЗДОЧКА] [ЧИСЛО 4]
        │
        ▼
   ┌──────────┐
   │  Парсер  │   токены → дерево, отражающее приоритеты
   └──────────┘
        │
        ▼
         (+)
        /   \
      (2)   (*)
           /   \
         (3)   (4)
        │
        ▼
   ┌──────────────┐
   │ Вычислитель  │   дерево → число
   └──────────────┘
        │
        ▼
        14
```

Разделение на этапы не формальность: лексер отвечает за «какие символы
допустимы», парсер — за «в каком порядке они могут стоять». Смешав их,
получаешь код, в котором невозможно разобраться и который невозможно
осмысленно тестировать.

---

## 3. Лексер

Превращает строку в список токенов и отбрасывает пробелы.

| Токен | Что распознаёт | Пример |
|---|---|---|
| `NUMBER` | Целое или дробное число | `42`, `3.14`, `0.5` |
| `PLUS` | Знак сложения | `+` |
| `MINUS` | Знак вычитания | `-` |
| `STAR` | Знак умножения | `*` |
| `SLASH` | Знак деления | `/` |
| `LPAREN` | Открывающая скобка | `(` |
| `RPAREN` | Закрывающая скобка | `)` |
| `EOF` | Конец ввода | — |

Правила:

- Пробелы и табуляции разделяют токены, но сами токенами не являются: `2+2`
  и `2 + 2` дают одинаковый список.
- Дробная часть отделяется точкой. Запятая недопустима — иначе `1,5` невозможно
  отличить от разделителя аргументов при будущем добавлении функций.
- Любой символ, не подходящий ни под один токен, — ошибка `UNKNOWN_CHAR`
  с указанием позиции.

Токен `EOF` добавляется в конец специально: парсеру нужен явный признак конца,
иначе каждая функция разбора должна отдельно проверять выход за границу списка.

**Каждый токен хранит позицию** символа в исходной строке. Без этого сообщение
об ошибке звучит как «синтаксическая ошибка» и не помогает вообще; с позицией —
показывает конкретное место.

## 4. Грамматика

Записана в форме, где `*` означает «ноль или более повторений»,
а вертикальная черта — выбор одной из альтернатив.

```
выражение  :=  слагаемое  ( ( "+" | "-" )  слагаемое )*

слагаемое  :=  множитель ( ( "*" | "/" )  множитель )*

множитель  :=  NUMBER
            |  "(" выражение ")"
            |  "-" множитель
            |  "+" множитель
```

Три правила — весь язык калькулятора.

### Как отсюда берутся приоритеты

Это главная идея рекурсивного спуска, и её стоит понять целиком.

Приоритет операций **нигде не задан явно** — ни таблицей, ни числами.
Он возникает из структуры грамматики.

Посмотри на цепочку: `выражение` состоит из `слагаемых`, а `слагаемое` состоит
из `множителей`. Значит умножение оказывается **глубже** в дереве, чем
сложение. А вычисление дерева идёт снизу вверх — сначала считаются листья,
потом узлы над ними.

Для `2 + 3 * 4` это даёт:

```
         (+)              сложение — верхний уровень, считается последним
        /   \
      (2)   (*)           умножение — уровнем ниже, считается первым
           /   \
         (3)   (4)
```

Результат `14`, а не `20`. Приоритет соблюдён, хотя мы его не программировали.

**Хочешь добавить возведение в степень** — вставляешь новый уровень между
`слагаемым` и `множителем`, и приоритет получается автоматически. Ничего
переписывать не нужно.

### Скобки

Правило `множитель := "(" выражение ")"` рекурсивно возвращает разбор
на самый верхний уровень. Поэтому внутри скобок снова доступны все операции,
а вложенность работает на любую глубину.

### Унарный минус

Правило `множитель := "-" множитель` тоже рекурсивно, поэтому `--5`
разбирается корректно (как `-(-5)`, то есть `5`). Унарный плюс добавлен для
симметрии: выражение `+5` — допустимая запись.

## 5. Парсер: рекурсивный спуск

**Каждой строчке грамматики соответствует одна функция.** Это буквальное
соответствие — в этом вся привлекательность метода: грамматика читается как
код, код читается как грамматика.

| Функция | Правило грамматики |
|---|---|
| `parse_expression()` | `выражение` |
| `parse_term()` | `слагаемое` |
| `parse_factor()` | `множитель` |

Каждая функция:

1. Разбирает то, что должна, вызывая функции уровнем ниже
2. Возвращает узел дерева
3. Если встретила не то, что ожидала, — сообщает синтаксическую ошибку
   с позицией

Парсер идёт по списку токенов слева направо и никогда не возвращается назад.
Отсюда название: спуск по уровням грамматики, рекурсивный из-за скобок.

### Проверка конца

После разбора всего выражения парсер обязан убедиться, что следующий токен —
`EOF`. Без этой проверки строка `2 + 2)` разберётся успешно: парсер прочитает
`2 + 2`, посчитает работу выполненной и не заметит лишнюю скобку.

### Ограничение глубины

Каждая открывающая скобка уводит парсер на уровень рекурсии глубже. Строка
из тысячи скобок вызовет переполнение стека — и падение будет выглядеть
необъяснимо, потому что причина не в логике, а в среде выполнения.

Поэтому глубина ограничена **50** уровнями с явной ошибкой `DEPTH_EXCEEDED`.
Это защита от намеренной атаки, а не от опечатки: осмысленные выражения такой
вложенности не имеют.

## 6. Вычислитель

Обходит дерево снизу вверх. Для каждого узла:

- Число — вернуть его значение
- Бинарная операция — вычислить обе ветви, применить операцию
- Унарный минус — вычислить ветвь, сменить знак

Здесь же проверяется деление на ноль — до выполнения операции, а не после.

**О типах результата.** Целочисленный результат возвращается целым числом,
дробный — числом с плавающей точкой: `4 / 2` даёт `2`, `5 / 2` даёт `2.5`.
Это удобнее человеку, чем `2.0` в первом случае.

Стоит помнить о свойстве чисел с плавающей точкой: `0.1 + 0.2` не равно ровно
`0.3` — это следствие двоичного представления дробей, а не ошибка калькулятора.
Хороший вопрос для защиты; при необходимости решается переходом на десятичную
арифметику (`decimal`).

## 7. Ошибки

| Код | Когда возникает | Пример |
|---|---|---|
| `UNKNOWN_CHAR` | Лексер встретил недопустимый символ | `2 $ 3` |
| `SYNTAX_ERROR` | Токены не складываются в грамматику | `2 + * 3`, `(2 + 3`, `2 + 2)` |
| `DIV_BY_ZERO` | Деление на ноль | `10 / 0`, `1 / (3 - 3)` |
| `DEPTH_EXCEEDED` | Вложенность скобок больше 50 | `((((((...))))))` |
| `NUMBER_TOO_LARGE` | Число или результат вне допустимого диапазона | очень длинная запись числа |
| `EXPR_TOO_LONG` | Выражение длиннее 1000 символов | — |

Все ошибки лексера и парсера несут **позицию символа**, которая передаётся
клиенту в поле `position` — см. [protocol.md](protocol.md).

## 8. Тестирование

Вычислительное ядро проверяется **без запуска сервера**: это обычная функция
«строка → число».

Что должно быть покрыто:

| Группа | Примеры |
|---|---|
| Простая арифметика | `2+2`, `10-3`, `6*7`, `8/2` |
| Приоритеты | `2+3*4` = 14, `2*3+4` = 10 |
| Скобки | `(2+3)*4` = 20, вложенные скобки |
| Унарный минус | `-5`, `-(2+3)`, `--5`, `2*-3` |
| Дробные числа | `0.5+0.5`, `1/3` |
| Пробелы | `2+2` и `  2  +  2  ` дают одно и то же |
| Ошибки | каждый код из таблицы выше |
| Границы | пустая строка, только пробелы, одно число, предельная вложенность |

Особое внимание — **тестам на ошибки**. Проверять нужно не только то, что
правильные выражения считаются правильно, но и то, что неправильные
отвергаются с нужным кодом. Калькулятор, который на `2 + * 3` возвращает
случайное число вместо ошибки, хуже, чем неработающий.

## 9. Возможные расширения

Все они укладываются в ту же схему и не требуют переписывания:

- **Возведение в степень** — новый уровень грамматики между `слагаемым`
  и `множителем`. Отличается правой ассоциативностью: `2^3^2` это `2^(3^2)`,
  а не `(2^3)^2`.
- **Остаток от деления** — добавляется на уровень `слагаемого`, рядом
  с умножением.
- **Функции** (`sqrt`, `abs`, `sin`) — новая альтернатива в правиле
  `множитель`, плюс токен идентификатора в лексере.
- **Константы** (`pi`, `e`) — распознаются как идентификаторы, подставляются
  вычислителем.
- **Переменные** (`let x = 5`) — требуют состояния на соединение и расширения
  протокола, а не только грамматики.
