# Программа и методика испытаний

Документ описывает, что и как проверяется в системе, и приводит результаты
последнего прогона.

---

## 1. Объект и цели испытаний

**Объект:** клиент-серверная система вычисления арифметических выражений.

**Цели:**

1. Убедиться, что границы сообщений восстанавливаются независимо от того, как
   поток байт поделён между чтениями.
2. Убедиться, что прикладной протокол корректно обрабатывает как правильные
   запросы, так и любые способы прислать некорректные данные.
3. Убедиться, что выражения вычисляются с соблюдением приоритета операций.
4. Убедиться, что сервер устойчив: ошибка клиента не приводит ни к разрыву
   соединения, ни к отказу сервера.
5. Убедиться, что несколько клиентов обслуживаются одновременно и не влияют
   друг на друга.

---

## 2. Средства и порядок проведения

| Параметр | Значение |
|---|---|
| Инструмент | `unittest` из стандартной библиотеки Python |
| Дополнительные пакеты | не требуются |
| Команда запуска | `python -m unittest discover` |
| Каталог | корень проекта |
| Предварительный запуск сервера | не требуется |

Интеграционные тесты поднимают сервер самостоятельно — в отдельном потоке, на
свободном порту, полученном у операционной системы. Это исключает конфликт с
запущенным вручную экземпляром и позволяет выполнять тесты параллельно с
обычной работой.

Запуск отдельного набора:

```bash
python -m unittest tests.test_calc
```

Подробный вывод с именами проверок:

```bash
python -m unittest discover -v
```

## 3. Уровни тестирования

### Модульный уровень

Проверяются отдельные компоненты в отрыве от сети. Наборы: `test_framing`,
`test_protocol`, `test_dispatcher`, `test_calc`.

Возможность такой проверки — следствие проектного решения: пакет `calc/` не
зависит от сокетов, поэтому вычисления тестируются как обычная функция
«строка → число». Смешение отладки синтаксического анализа с отладкой сетевого
обмена существенно затрудняет поиск причины отказа.

### Интеграционный уровень

Проверяется система целиком через реальные сокеты TCP. Набор
`test_integration`.

## 5. Методика по разделам

### 5.1 Границы сообщений (`test_framing.py`)

Проверяемое свойство: **результат не зависит от разбиения потока байт на
чтения.**

| Проверка | Метод |
|---|---|
| Одно сообщение целиком | Подача завершённой строки |
| Несколько сообщений за одно чтение | Подача `AAA\nBBB\n` одним куском |
| Сообщение разрезано между чтениями | Подача по частям `hel`, `lo`, `\n` |
| Разрез посреди стыка сообщений | Подача `first\nsec`, затем `ond\n` |
| Побайтовая подача | Каждый байт отдельным вызовом |
| Разрез внутри многобайтового символа | Подача `\xd0`, затем `\xbf\n` |
| Возврат каретки от telnet | Подача `ping\r\n` |
| Кадр по границе размера | Лимит 8 байт, сообщение ровно 8 с разделителем |
| Кадр на байт длиннее | Лимит 8 байт, сообщение 9 байт |
| Поток без разделителя | Лимит 8 байт, 8 байт без завершения |
| Накопление переполнения | Две подачи по 4 байта при лимите 8 |

Проверка с разрезом внутри многобайтового символа существенна: кириллическая
буква занимает в UTF-8 два байта, и попытка декодировать неполный буфер
привела бы к отказу. Реализация работает с байтами, декодирование выполняется
после сборки.

### 5.2 Протокол (`test_protocol.py`)

Поскольку данные поступают из сети, проверяется не только успешный случай, но
и каждый способ прислать некорректные данные.

| Проверка | Входные данные |
|---|---|
| Минимальный запрос | `{"cmd":"ping"}` |
| Сохранение идентификатора | `{"cmd":"ping","id":42}` и строковый вариант |
| Не JSON | произвольный текст |
| JSON, но не объект | `["ping"]` |
| Недопустимая кодировка | байт, невозможный в UTF-8 |
| Отсутствует поле `cmd` | `{"expr":"2+2"}` |
| `cmd` не строка | `{"cmd":123}` |
| `cmd` пустая строка | `{"cmd":""}` |
| Логическое значение в поле `id` | `{"cmd":"ping","id":true}` |
| Число вне диапазона | `{"cmd":"history","limit":999}` |
| Ответ всегда однострочный | Результат с переводом строки внутри |
| Поле `status` присутствует всегда | Успешный и ошибочный ответы |

Проверка с `id: true` не формальность: в Python логический тип является
подклассом целого, и без явной проверки значение `true` было бы принято как
единица.

### 5.3 Вычисления (`test_calc.py`)

**Арифметика и приоритеты**

| Выражение | Ожидается | Что подтверждает |
|---|---|---|
| `2+2` | 4 | Базовая операция |
| `2+3*4` | 14 | Умножение раньше сложения |
| `2*3+4` | 10 | То же при другом порядке |
| `10-8/2` | 6 | Деление раньше вычитания |
| `(2+3)*4` | 20 | Скобки переопределяют порядок |
| `((2+3)*(4-1))/5` | 3 | Вложенные скобки |
| `10-3-2` | 5 | Левая ассоциативность вычитания |
| `100/10/2` | 5 | Левая ассоциативность деления |

Проверки левой ассоциативности существенны: при неверной реализации `10-3-2`
дало бы 9 вместо 5.

**Унарные знаки**

`-5`, `+5`, `-(2+3)`, `--5`, `2*-3`, `-2*3`.

**Типы результата**

`4/2` даёт целое `2`, `5/2` — дробное `2.5`, `1.5+1.5` — целое `3`.

**Ошибки**

`10/0`, `1/(3-3)`, `2 + * 3`, `(2+3`, `2+2)`, `()`, пустая строка, только
пробелы, `2 +`, `2 3`, `2 @ 3`, `2 ** 3`, `1.2.3`, `5.`

Проверка `2+2)` существенна: без контроля достижения конца ввода анализатор
разобрал бы `2+2`, счёл работу выполненной и не заметил лишнюю скобку.

**Ограничения**

| Проверка | Входные данные |
|---|---|
| Длина выражения | 1201 символ |
| Глубина вложенности | 100 уровней скобок |
| Длина записи числа | 200 цифр |
| Величина целого результата | произведение четырёх стозначных чисел |
| Переполнение дробного | произведение четырёх больших дробных |

**Безопасность**

| Проверка | Входные данные | Ожидается |
|---|---|---|
| Код Python не выполняется | `__import__('os').system('echo hacked')` | Отказ |
| Имена не распознаются | `open` | Отказ |
| Степень не поддерживается | `9**9**9` | Отказ |

Первая проверка воспроизводит атаку, возможную при использовании `eval()`.

### 5.4 Диспетчеризация и история (`test_dispatcher.py`)

| Проверка |
|---|
| Вызов зарегистрированного обработчика |
| Передача запроса и состояния соединения в обработчик |
| Неизвестная команда возвращает соответствующий код |
| Сообщение об ошибке перечисляет доступные команды |
| Повторная регистрация команды запрещена |
| Отображение ошибки вычисления в код протокола |
| Позиция ошибки доходит до уровня протокола |
| История накапливается |
| Неудачное вычисление в историю не попадает |
| История ограничивается запрошенным количеством |
| История разных соединений не пересекается |

### 5.5 Взаимодействие через сокеты (`test_integration.py`)

| Проверка | Методика |
|---|---|
| Проверка связи | Команда `ping` через реальный сокет |
| Вычисление | Команда `calc` с выражением |
| Возврат идентификатора | Запрос с полем `id` |
| Ошибка не разрывает соединение | Деление на ноль, затем `ping` |
| Позиция ошибки доходит до клиента | Выражение с недопустимым символом |
| История в пределах соединения | Два вычисления, затем `history` |
| История нового соединения пуста | Переподключение |
| Конвейер запросов | Два запроса одной отправкой |
| Завершение по команде | `quit`, затем проверка закрытия |
| Превышение размера кадра | Отправка 5000 байт без разделителя |
| Живучесть после нарушений | Подключение после разрыва |
| Одновременная работа | Пять клиентов подключены разом |
| Изоляция историй | Два клиента считают разное |
| Параллельные вычисления | Три потока синхронизированы барьером |
| Предел подключений | Лимит 2, подключение третьего |

Проверка одновременной работы построена так, что однопоточный сервер её не
пройдёт: пять клиентов должны быть подключены **одновременно**, что
контролируется через счётчик активных соединений.

## 7. Дефекты, выявленные испытаниями

Все четыре дефекта обнаружены выполнением программы, а не чтением кода.

### Дефект 1. Искажение журнала при перенаправлении вывода

**Проявление.** Чтение вывода сервера сторонним процессом завершалось ошибкой
декодирования.

**Причина.** При перенаправлении вывода в файл или канал Python в Windows
использует системную кодировку вместо UTF-8.

**Устранение.** Поток вывода принудительно переключён на UTF-8 с заменой
непредставимых символов.

### Дефект 2. Штатный обрыв связи записывался как ошибка

**Проявление.** Закрытие клиента порождало запись уровня `ERROR`, хотя ситуация
штатная.

**Причина.** Перехватывался только `ConnectionResetError`; Windows при обрыве
установленного подключения возвращает `ConnectionAbortedError`.

**Устранение.** Перехват общего предка `ConnectionError`. Перечисление
конкретных типов ведёт к пропуску одного из них на другой платформе.

### Дефект 3. Потеря уведомления о превышении размера кадра

**Проявление.** Клиент вместо кода `FRAME_TOO_LONG` получал сообщение об
аварийном разрыве соединения.

**Причина.** Закрытие сокета при наличии непрочитанных входящих данных
приводит к отправке сигнала аварийного сброса, при котором ранее отправленные
данные могут быть отброшены.

**Устранение.** Корректное закрытие: уведомление о прекращении передачи, затем
ограниченное вычитывание остатка, затем закрытие. Ограничения по объёму и
времени обязательны — иначе клиент, продолжающий передачу, удерживал бы поток
неограниченно долго.

**Значение.** Дефект показывает, что закрытие сокета не гарантирует доставку
ранее отправленных данных.

### Дефект 4. Неверное ожидание кода ошибки в тестах

**Проявление.** Два теста ожидали код `UNKNOWN_CHAR` для выражения `2 ** 3`.

**Причина.** Ошибка в тестах, а не в программе: символ `*` допустим лексически,
поэтому ошибка является синтаксической.

**Устранение.** Тесты исправлены, различие между лексической и синтаксической
ошибкой описано в [grammar.md](grammar.md).

## 8. Не покрытое автоматическими тестами

Проверяется вручную:

| Область | Способ проверки |
|---|---|
| Интерактивный ввод в клиенте | Запуск и ввод выражений |
| Прерывание сервера по `Ctrl+C` | Запуск и остановка |
| Запись журнала в файл | Запуск с аргументом `--log-file` |
| Работа по локальной сети | Запуск с `--host 0.0.0.0`, подключение с другой машины |
| Таймаут бездействия | Требует ожидания 300 секунд |

Порядок ручной проверки описан в [user-guide.md](user-guide.md).
