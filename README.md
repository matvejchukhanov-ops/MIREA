# Калькулятор выражений — система клиент-сервер

Учебный проект. Сервер принимает по TCP арифметические выражения, разбирает их
собственным парсером и возвращает результат. Клиент — консольное приложение.

Ключевая особенность: **транспорт и разбор выражений реализованы вручную**, без
веб-фреймворков и без `eval()`. Это и есть содержание задания — всё, что обычно
прячут библиотеки, здесь написано явно.

## Стек

| Компонент | Что используется | Почему |
|---|---|---|
| Язык | Python 3.11+ | Богатая стандартная библиотека, быстрая разработка |
| Транспорт | `socket` (stdlib) | Голые TCP-сокеты — суть задания |
| Конкурентность | `threading` (stdlib) | Поток на клиента: просто и наглядно |
| Сериализация | `json` (stdlib) | Читаемо, расширяемо, разбирается одной строкой |
| Логирование | `logging` (stdlib) | Стандартный механизм, настраиваемые уровни |
| Конфигурация | `argparse` + переменные окружения | Хост и порт не зашиты в код |
| Тесты | `unittest` (stdlib) | Не требует установки: тесты запускаются там же, где код |

**Внешних зависимостей нет вообще** — ни у кода, ни у тестов. Сервер, клиент
и проверки запускаются на чистом Python, без `pip install`.

## Технические решения

| Пункт | Решение | Обоснование |
|---|---|---|
| Протокол транспорта | TCP, `AF_INET` / `SOCK_STREAM` | Нужна гарантия доставки и порядка; UDP для калькулятора не подходит |
| Границы сообщений | Разделитель `\n` (одно сообщение — одна строка) | TCP не сохраняет границы сообщений. Данные текстовые, так что разделителя достаточно, а сервер можно проверять вручную через `telnet` |
| Формат сообщений | JSON в UTF-8 | Расширяемость: новые поля не ломают старых клиентов |
| Модель сервера | Поток на клиента (`threading.Thread`) | Блокирующий `accept()` не даёт обслуживать нескольких клиентов в одном потоке. Путь масштабирования — `asyncio`, описан в архитектуре |
| Вычисление выражений | Собственный лексер + парсер рекурсивным спуском | `eval()` исключён: он выполняет произвольный код и превращает сервер в дыру для удалённого выполнения |
| Хранение | В памяти, история на соединение | По заданию персистентность не требуется; БД усложнила бы без пользы |
| Аутентификация | Отсутствует | Не требуется. Место под неё заложено в протоколе (см. `docs/protocol.md`) |
| Шифрование | Отсутствует | Работа на `localhost`. Переход на TLS описан как возможное расширение |
| Клиент | Консольный на Python | Браузер не умеет открывать TCP-сокет, поэтому React потребовал бы HTTP-шлюза поверх ядра. От варианта отказались: он добавляет слой, ничего не добавляя к теме задания |

## Структура репозитория

```
client-server/
├── common/                  код, общий для обеих сторон
│   └── framing.py           границы сообщений поверх TCP
├── server/                  серверная часть
│   ├── main.py              точка входа, разбор аргументов
│   ├── config.py            хост, порт, лимиты
│   ├── tcp_server.py        слушающий сокет, цикл accept, запуск потоков
│   ├── connection.py        обслуживание одного клиента, цикл запрос-ответ
│   ├── protocol.py          сборка и разбор сообщений, коды ошибок
│   ├── dispatcher.py        сопоставление команды с обработчиком
│   ├── handlers.py          calc, ping, history, quit
│   ├── session.py           состояние одного соединения
│   ├── logging_setup.py     настройка логов
│   └── calc/                вычислительное ядро (сети не знает)
│       ├── lexer.py         строка -> список токенов
│       ├── parser.py        токены -> дерево разбора (рекурсивный спуск)
│       ├── evaluator.py     дерево -> число
│       └── errors.py        исключения калькулятора
├── client/                  клиентская часть
│   ├── main.py              точка входа, цикл ввода
│   └── connection.py        подключение, фрейминг, отправка и приём
├── docs/
│   ├── protocol.md          спецификация протокола
│   ├── architecture.md      архитектура, потоки, жизненный цикл соединения
│   └── grammar.md           грамматика выражений и устройство парсера
└── tests/                   тесты (логика отдельно от сети)
```

Два разделения здесь принципиальны.

**`common/` общий для клиента и сервера.** Проблема границ сообщений
симметрична: ответ сервера может прийти по частям точно так же, как запрос
клиента. Дублировать этот код в двух местах означало бы чинить каждую ошибку
дважды.

**`server/calc/` ничего не знает о сокетах.** Функция «строка → число»
тестируется без запуска сервера. Смешивать отладку парсера и отладку сети —
верный способ потерять день, не понимая, что именно сломалось.

## Запуск

Нужен только Python 3.11+. Устанавливать ничего не требуется.

Сервер (первым, в отдельном окне терминала):

```bash
python -m server.main
```

Клиент (во втором окне):

```bash
python -m client.main
```

Параметры по умолчанию — `127.0.0.1:9000`. Изменить:

```bash
python -m server.main --host 127.0.0.1 --port 9000 --log-level DEBUG
```

| Аргумент сервера | Переменная окружения | По умолчанию |
|---|---|---|
| `--host` | `CALC_HOST` | `127.0.0.1` |
| `--port` | `CALC_PORT` | `9000` |
| `--log-level` | `CALC_LOG_LEVEL` | `INFO` |
| `--log-file` | — | не пишется |
| — | `CALC_IDLE_TIMEOUT` | `300` секунд |
| — | `CALC_MAX_CONNECTIONS` | `64` клиента одновременно |
| — | `CALC_MAX_FRAME_SIZE` | `4096` байт |
| — | `CALC_BACKLOG` | `16` в очереди подключений |

Уровень `DEBUG` показывает каждый принятый байт — при отладке сети это основной
инструмент.

Остановка сервера — `Ctrl+C`. Выход из клиента — команда `quit` или `Ctrl+C`.

### Что можно вводить в клиенте

| Ввод | Команда протокола | Что делает |
|---|---|---|
| `2 + 3 * (4 - 1)` | `calc` | вычисляет выражение |
| `ping` | `ping` | проверка связи |
| `history`, `history 5` | `history` | последние вычисления этого соединения |
| `quit` | `quit` | выход |
| `{"cmd":"ping","id":1}` | отправляется как есть | отладка протокола |

Пример сеанса:

```
> 2 + 3 * 4
14
> (2 + 3) * 4
20
> 10 / 4
2.5
> 10 / 0
Ошибка [DIV_BY_ZERO]: Деление на ноль
> 12 + $
Ошибка [UNKNOWN_CHAR]: Недопустимый символ '$'
  12 + $
       ^
> history
  2 + 3 * 4 = 14
  (2 + 3) * 4 = 20
  10 / 4 = 2.5
```

Неудачные вычисления в историю не попадают. Указатель под выражением строится
по полю `position` из ответа — сервер сообщает не только что не так, но и где.

Последняя строка таблицы — отладочная лазейка: всё, начинающееся с `{`, уходит
на сервер без изменений. Так можно вручную проверить, как протокол реагирует
на нарушения, не переписывая клиент.

## Тесты

```bash
python -m unittest discover
```

Устанавливать ничего не нужно. Тесты покрывают логику, не зависящую от сети:

| Файл | Что проверяет |
|---|---|
| `test_framing.py` | Результат не зависит от того, как поток байт поделён между чтениями |
| `test_protocol.py` | Разбор запросов и все способы прислать мусор |
| `test_dispatcher.py` | Поиск обработчика, коды ошибок, история |
| `test_calc.py` | Лексер, приоритеты, скобки, унарный минус, ошибки, лимиты |
| `test_integration.py` | Настоящие сокеты: протокол, параллельные клиенты, предел подключений |

Всего 129 тестов. `test_calc.py` работает без сети вообще — это чистая функция
«строка → число». `test_integration.py` поднимает сервер в отдельном потоке
на свободном порту и разговаривает с ним через реальный TCP.

## Этапы работы

| Этап | Результат | Как проверяется | Статус |
|---|---|---|---|
| 1 | Сервер принимает подключение, возвращает эхо | Запустить сервер и клиент, ввести текст, увидеть отражение | **готов** |
| 2 | Фрейминг по `\n` | Два сообщения подряд без задержки не склеиваются | **готов** |
| 3 | Протокол JSON, команда `ping` | Ответ приходит корректным JSON | **готов** |
| 4 | Лексер и парсер, считается `2+2` | Тесты парсера без запуска сервера | **готов** |
| 5 | Приоритеты, скобки, унарный минус | Набор выражений с известными ответами | **готов** |
| 6 | Коды ошибок, история, сервер не падает | Деление на ноль возвращает `DIV_BY_ZERO`, соединение живо | **готов** |
| 7 | Потоки: несколько клиентов одновременно | Пять клиентов подключены разом, считают параллельно | **готов** |
| 8 | Логи, конфигурация, тесты, README | 129 тестов проходят | **готов** |
| 9 | *(опционально)* HTTP-шлюз и React-клиент | — | **отменён** |

Каждый этап оставляет работающую программу — так проще откатываться и нагляднее
история коммитов.

Этап 9 отменён сознательно. Браузер не может открыть TCP-сокет: из JavaScript
доступны только HTTP и WebSocket. React-клиент потребовал бы поднять поверх
ядра ещё один сервер-посредник — то есть добавить слой, который к теме задания
ничего не добавляет, а сетевую часть, наоборот, спрячет за фреймворком.
